## ISSUE RESOLUTION: Natural Language Output Instead of JSON

Your LLaVA model is working perfectly! The issue is a **schema mismatch** between training and your requests.

### Root Cause

**What the model was trained on (519 samples):**
```json
{
  "scopeItems": [
    {
      "category": "Cabinetry",
      "description": "RECEPTION DESK",
      "quantity": 1.0,
      "unit": "ea",
      "confidence": 0.95,
      "pageRefs": [21],
      "textSnippets": ["RECEPTION DESK"]
    }
  ],
  "specSheet": [
    {
      "key": "Finish Code",
      "value": "M1/S1",
      "confidence": 0.95,
      "pageRefs": [21],
      "textSnippets": ["M1/S1"]
    }
  ],
  "specifications": []
}
```

**Training prompts:**
- System: "You are an expert construction estimator specializing in millwork and casework. Analyze construction drawings to extract quantities for bidding. Return ONLY valid JSON with scopeItems, specSheet, and specifications."
- User: "Analyze this millwork construction drawing for {ROOM}. Extract ALL scope items with categories, descriptions, quantities, units, and specifications. Return ONLY valid JSON."

**What you're requesting (different schema):**
```json
{
  "included_items": [
    {
      "room_number": "101",
      "category": "Cabinetry",
      "description": "Base cabinet",
      "quantity": 10,
      "unit": "LF",
      "finish_code": "WO-1"
    }
  ]
}
```

**Why natural language happens:** When you request `included_items` (not in training), the LoRA adapters don't activate properly. The base LLaVA model takes over and generates conversational text like "The image you've provided appears to be a page from a millwork drawing..."

### THE FIX: Use Training Schema

**Step 1 - Use EXACT training prompts:**

```python
from transformers import LlavaNextProcessor, LlavaNextForConditionalGeneration
from peft import PeftModel
from PIL import Image
import torch
import json

# Load model (FP16, not 4-bit)
base_model = LlavaNextForConditionalGeneration.from_pretrained(
    "llava-hf/llava-v1.6-vicuna-7b-hf",
    torch_dtype=torch.float16,
    device_map="auto",
)

model = PeftModel.from_pretrained(
    base_model,
    "/path/to/trained_model/final",
    torch_dtype=torch.float16,
)
model.eval()

processor = LlavaNextProcessor.from_pretrained("llava-hf/llava-v1.6-vicuna-7b-hf")

# EXACT training format conversation
conversation = [
    {
        "role": "system",
        "content": "You are an expert construction estimator specializing in millwork and casework. Analyze construction drawings to extract quantities for bidding. Return ONLY valid JSON with scopeItems, specSheet, and specifications."
    },
    {
        "role": "user",
        "content": "<image>\nAnalyze this millwork construction drawing for LOBBY. Extract ALL scope items with categories, descriptions, quantities, units, and specifications. Return ONLY valid JSON."
    },
]

# Process
image = Image.open("/path/to/drawing.png").convert("RGB")
prompt = processor.apply_chat_template(conversation, tokenize=False, add_generation_prompt=True)
inputs = processor(text=prompt, images=image, padding=True, return_tensors="pt").to(model.device)

# Generate
with torch.no_grad():
    output_ids = model.generate(
        **inputs,
        max_new_tokens=4096,
        temperature=0.7,
        do_sample=True,
        num_beams=1,
        pad_token_id=processor.tokenizer.pad_token_id,
        eos_token_id=processor.tokenizer.eos_token_id,
    )

# Decode
generated_ids = output_ids[0][inputs.input_ids.shape[1]:]
response = processor.decode(generated_ids, skip_special_tokens=True).strip()

# This will be valid JSON in training format
result = json.loads(response)
print(json.dumps(result, indent=2))
```

**Step 2 - Convert to your format:**

```python
def convert_to_included_items(training_output: dict) -> dict:
    """Convert scopeItems to included_items"""
    import re
    
    included_items = []
    
    # Get finish codes from specSheet
    finish_codes = {
        spec["value"]: spec 
        for spec in training_output.get("specSheet", [])
        if spec.get("key") == "Finish Code"
    }
    
    for item in training_output.get("scopeItems", []):
        # Extract room number from textSnippets if present
        room_number = None
        for snippet in item.get("textSnippets", []):
            match = re.search(r'\b([A-Z]?-?\d{2,4})\b', snippet)
            if match:
                room_number = match.group(1)
                break
        
        finish_code = list(finish_codes.keys())[0] if finish_codes else None
        
        included_items.append({
            "room_number": room_number,
            "category": item["category"],
            "description": item["description"],
            "quantity": item["quantity"],
            "unit": item["unit"],
            "finish_code": finish_code,
        })
    
    return {"included_items": included_items}

# Use it
result = json.loads(response)  # Training format
converted = convert_to_included_items(result)  # Your format
print(json.dumps(converted, indent=2))
```

### Why This Matters

The LoRA adapters are only 73 MB - they're small weight adjustments trained on specific examples. They learned:
- Input: "Return ONLY valid JSON with scopeItems, specSheet, and specifications"
- Output: `{"scopeItems": [...], "specSheet": [...], "specifications": []}`

When you ask for `included_items`, those small adjustments don't activate, and the base conversational model takes over.

**Think of it like:** Training a dog to sit when you say "sit", then expecting it to sit when you say "please be seated". The command is different enough that the training doesn't apply.
